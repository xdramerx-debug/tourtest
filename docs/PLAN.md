# План реализации — система организации гольф-турнира

Бриф: 25 модулей, стандарты R&A / USGA / WHS, адаптированные под клубный уровень.
Стек (по решению заказчика): **чистый HTML/JS + Firebase Realtime Database**, без сборщика.

## 2.2. User stories (ключевые)

- Как **игрок**, сканирую QR со скоркарты и вижу своё время старта, группу, Playing HCP и удары по лункам.
- Как **маркер**, ввожу результат по лунке (± или цифрой); карточка сама считает Net/Stableford и шлёт на лидерборд; в конце подписываю — дальше правки закрыты.
- Как **организатор**, нажимаю «Сгенерировать группы» — стартовый лист собрался по гандикапам, я публикую его и печатаю PDF с QR.
- Как **судья**, вижу на хабе баннер приостановки, когда комитет его выставил (узел `suspension`).
- Как **зритель в клубхаусе**, смотрю TV-режим: крупные позиции, ротация категорий, часы.
- Как **новый игрок**, заполняю форму регистрации и сразу получаю QR для стойки check-in.

## 3. План по релизам

### MVP (готов, в этом коммите)
Живой цикл турнира «от заявки до результата»: регистрация → подтверждение → стартовый лист → check-in →
live-скоринг (QR) → лидерборд (real-time, TV) → призы → правила → печать ключевых документов (лист A4,
скоркарта A4, карточка A6, правила, лидерборд). Расчёты по WHS: Playing HCP (SCA 85% stroke / 95% stableford —
настраивается), распределение ударов по Stroke Index, Max Score Rule (NDB), Stableford, To Par, countback (USGA).

### V2 (после первого турнира)
1. Firebase Hosting deploy + кастомный домен, HTTPS, CDN (сам hosting даёт).
2. Rules RTDB: чтение для всех, запись только для admin (консоль) + отдельные write-paths для
   scorecards/prizes (маршалы) — см. DATA_MODEL.md.
3. Протоколы (PDF-генератор 7 типов документов + ZIP) и сертификаты с верификацией.
4. Личный кабинет + Firebase Auth (role-based: судья/оператор/волонтёр), полная админка, audit log.
5. Офлайн-скоринг: IndexedDB-очередь + ресинк (для «мёртвых зон» поля).
6. Погода + push/SMS-уведомления (Cloud Functions), email-цепочки (SendGrid).
7. Стойка check-in и бейджи (печать), командный зачёт, карта поля с QR на ти.
8. PWA: manifest + service worker (кэш страниц, установка «как приложение»).

### V3 (масштаб)
- Мультиязычность (ru/en/…) по i18n-словарю.
- REST API для внешних табло + embed-iframe лидерборда.
- Верификация гандикапов через API федераций (RGF/WHS).
- Платежи (Stripe): Cloud Function webhook + инвойсы, возвраты.
- Телеграм/WhatsApp-бот, аналитика QR-сканов, отчёты спонсоров, архив и Hall of Fame.
- Нагрузка 500+ клиентов: RTDB легко тянет тысячи подписчиков на лидерборд; тяжёлые расчёты
  (статистика) переносим в Cloud Functions + кэш-узел `stats`.

## 4. Технические заметки
- **PDF**: печать через браузер (print CSS, `@page` A4/A6, альбом/портрет) — корректный кириллический текст,
  QR с canvas в документы без утяжеления. Кнопки «PDF» = print → «Сохранить как PDF». (jsPDF с TTF-шрифтом
  — опция V2, если нужен автоматический download без диалога.)
- **Real-time**: RTDB client = WebSocket; лидерборд обновляется при любом изменении данных (нет поллинга).
- **Безопасность**: web-конфиг публичный (нормально). Test mode живёт 30 дней — перед туром обязательно
  перевести Rules в боевые (DATA_MODEL.md). Админка пока без авторизации — V2 закрывает ролями.
- **Демо-режим**: пока база пуста, сайт работает на встроенных данных (12 игроков, 3 группы, призовые),
  правки живут в localStorage; при появлении `tournaments/<id>` переключение автоматическое.
