# REVIEW.md — источник правды №13. Точки апрува: что проверяет человек

> Статус: DRAFT до апрува Фазы 0 · Версия: 0.1 · Дата: 2026-09-18
> Апрув фиксируется комментарием/approve в соответствующем PR. Без апрува следующая фаза не начинается.

## Точка 0 — после Фаза 0 (этот PR)

Человек проверяет:
- [ ] 16 источников правды содержательны, непротиворечивы, покрывают бриф (PRODUCT/…/ESTIMATE).
- [ ] Лог решений PRODUCT.md §8 принят (особенно: D1 локали, D3 SSE, D4 PIN-вход, D6 legacy-референс, **D7 адаптация ветвления — сессионная ветка вместо variant/*/design/* веток**, D8 демо-режим).
- [ ] Варианты A/B/C (VARIANTS.md) и 5 дизайнов (DESIGNS.md) — как ожидалось; таблица различий убедительна (≥7/10 любая пара).
- [ ] NFR-бюджеты реалистичны и измеримы; нет конфликтов NFR ↔ DESIGNS ↔ ADAPTIVE ↔ FORMATS.
- [ ] ESTIMATE.md адекватен; правило >30% понятно.
- [ ] Список сознательных упрощений правил (RULES.md §10) одобрен.

Что агент прикладывает: сам PR 16 файлов; отчёт по форме (сделано/файлы/метрики/вопросы).

## Точка 1 — после Фаза 1 (техкаркас)

Человек проверяет:
- [ ] Монорепо собирается с нуля по DEPLOY.md/CONTRIBUTING за ≤15 мин (чистая машина/CI).
- [ ] Packages core/scoring-engine/sync/tokens/design-system типизированы; правила импортов соблюдены (lint-boundaries).
- [ ] Scoring-engine: unit-тесты ≥90% строк, все сценарии RULES §11 и FORMATS «матрица 10» зелёные.
- [ ] Sync: контрактные тесты идемпотентности/конфликтов/резюма; демо-стенд сервера поднимается одной командой.
- [ ] Дизайн-токены покрывают 5 тем × режимы (dark/sun/reduced-motion); design-system рендерит примитивы на всех темах (storybook-подобная галерея).
- [ ] CI: lint/typecheck/unit/build/e2e-smoke/Lighthouse — зелёные и в рамках бюджета времени.

Приложено: скринкаст `npm install && npm run build && npm test`, отчёт покрытия, карта пакетов, логи CI.

## Точка 2 — после Фаза 2 (база A + первый дизайн A×1)

Человек проверяет:
- [ ] Весь функционал варианта A (VARIANTS.md, FEATURES.md по A) работает end-to-end с реальным сервером.
- [ ] Расширенный чек-лист 32/32 (см. чек-листы ниже); доказательства приложены полностью.
- [ ] Дизайн A×1 соответствует Heritage Green и отличен от заглушек каркаса; полевые режимы (sun/dark/перчатки) убедительны на скринах.
- [ ] UX-критерии подтверждены замерами (USABILITY-протокол, scorecard SUCCESS.md).

Решение: «эталон принят» → Фаза 3 возможна; «нет» → правила отката (вернуться к базе A).

## Точка 6 — сводная таблица 3×5

Человек проверяет:
- [ ] Таблица 15 сборок: статус чек-листов, отклонения NFR, scorecard-метрики, скрин-матрица.
- [ ] North Star посчитан честно (журнал «с первого/второго раза»).
- [ ] Рекомендация merge-порядка обоснована (MATRIX.md-сценарии + метрики).

## Точка 7 — перед merge любой сборки в main

- [ ] Полный чек-лист сборки зелёный **на актуальном main после rebase**; CI до конца (включая ночной набор для приоритетных).
- [ ] Security-чек и diff бандла против baseline в PR.
- [ ] Тег `vX.Y-{variant}{design}` будет поставлен после merge (план в PR).

## Прочие обязательные апрувы (вне графика фаз)

| Триггер | Что человек решает |
|---|---|
| Конфликт источников правды (NFR↔DESIGNS↔ADAPTIVE↔FORMATS) | Какой файл прав (иерархия PRODUCT.md) + правка через PR |
| Мажорное обновление библиотеки | Принять/отклонить по таблице «выигрыш/риски/бандл» |
| Расход > ESTIMATE.md на 30% | Декомпозиция / сокращение объёма / новый план |
| Новый формат/фича сверх VARIANTS.md/FORMATS.md | Добавить источник правды + перепланировать |
| «Упрощение» правил гольфа | Обновить RULES.md §10 или отказать |

## Доказательства, обязательные в PR сборки (шаблон)

```
## Чек-лист минимум: 10/10 (приложить прогон)
## Расширенный чек-лист (приоритетные): 32/32
## Скрины: desktop 1440 / tablet 768 / mobile 375 / landscape
## Солнце-режим: скрины + axe-отчёт контраста
## Lighthouse JSON: главная, счётокарта
## Deep links: curl-карта роутов (все 200)
## Offline: лог E1 (время sync __ с, потерь 0)
## Real-time: свежесть p50/p95 __/__ с на 100 обновлений
## Screen reader логи (приоритетные): 3 сценария
## Таблица различий дизайна от соседних: ≥7/10
## Diff бандла: __ КБ (было → стало)
## Отклонения от NFR (если есть): таблица
## Self-review: чек-лист прогнан до открытия PR, подпись
```

## Стоп-краны (агент обязан остановиться и спросить)

- 3+ PR за час без апрува. · Diff >500 строк без объяснения.
- Конфликт NFR ↔ DESIGNS ↔ ADAPTIVE ↔ FORMATS.
- Расхождение с ESTIMATE.md >30%. · Более 1 открытого неопределённого вопроса.
- 3+ сборки не проходят чек-лист. · Попытка «упростить» правила гольфа без согласования.
