# ADAPTIVE.md — источник правды №8. Адаптивность и полевые условия

> Статус: DRAFT до апрува Фазы 0 · Версия: 0.1 · Дата: 2026-09-18
> Одинаков для всех 15 сборок. Согласован с DESIGNS.md (там — стиль, здесь — поведение). При конфликте приоритет NFR.md.
> Проверочная матрица ширин: **320 / 375 / 414 / 768 / 1024 / 1280 / 1440 / 1920** px + ландшафт (667×375, 926×428, 1366×768). Каждая сборка проходит её в CI-скриншотах.

## 1. Режимы раскладки

| Режим | Ширина | Принцип |
|---|---|---|
| `compact` | 320–767 | Один столбец, карточки, нижние листы/панели, ввод одной рукой |
| `medium` | 768–1023 | Два столбца там, где естественно; сетка счётокарты допустима |
| `wide` | 1024–1919 | Полные таблицы, боковые панели, hover-состояния |
| `ultra` | ≥1920 | Контент ограничен max-width дизайна (DESIGNS.md), без растягивания таблиц в кашу |

Ландшафт ≤767px высотой считается `compact` + специальные правила §7.

## 2. Счётокарта

| Ширина | Поведение |
|---|---|
| `compact` | **Карточный вид**: одна лунка крупно (номер, пар, SI, длина), большой Numpad/чипы быстрого ввода в нижней трети (большепалец-зона), sticky-итог «To par / Thru» сверху. Свайп влево/вправо — лунки; свайп вверх/тап по имени — переключение игрока (маркер-режим). Без горизонтального скролла (жёсткий запрет) |
| `medium` | Допустима **сетка лунка×игрок** до 4 игроков, иначе карточный вид с вкладками игроков |
| `wide`/`ultra` | Сетка лунка×игрок (OUT/IN блоки по 9), sticky колонка игроков и шапка лунок, ввод из ячейки (поповер Numpad у ячейки, не уезжающий за экран) |
| Все | Текущая лунка авто-вычисляется (первая непустая с конца сыгранных = «Thru+1») и подсвечена; после ввода — авто-переход на следующую лунку (отключаемо в настройках) |

Ввод числа: тап по клавише → мгновенный локальный рендер (≤100 мс) → фоновая отправка; ячейки «в очереди» помечены индикатором sync (стиль — по дизайну, семантика едина).

## 3. Лидерборд

| Ширина | Колонки (приоритет слева) |
|---|---|
| 320–374 | Pos · Игрок (инициалы + фамилия сокращённо) · To par · Thru |
| 375–767 | Pos · Игрок · To par · Thru · Today/Pts |
| 768–1023 | + Gross · Net · Rd |
| ≥1024 | + Флайт · Out/In · Изм. позиции · Updated |

- Скрытые колонки — **не в горизонтальный скролл**, а в раскрытие строки по тапу (детали: hole-by-hole, SI-удары, история раундов).
- Строка приоритетных колонок никогда не обрезает To par/Thru целиком; имя игрока truncate с middle-ellipsis «И. Фамилия».
- На `compact` — липкая шапка таблицы + липкий фильтр-бар; на `wide` фильтры — боковая панель.
- Изменения позиций подсвечиваются дельта-миганием ≤3 с (стиль дизайна), без пересортировки «под пальцем»: пересорт происходит только когда строка вне вьюпорта или через 3 с после последнего касания таблицы.
- Плотность строк по дизайну (DESIGNS.md), но тач-строка ≥48px физически.

## 4. Графики и аналитика (вариант C; ленивые)

- `compact`: heatmap лунок → горизонтальный список чипов «сложность» (без интерактивного ховера); тренды — один график на экран, pinch-zoom запрещён, есть кнопки масштаба.
- `medium`+ : полноценные интерактивные графики.
- Слабая сеть: графики не грузятся вообще (нет чанка в precache; skeleton заменяется текстовой сводкой).

## 5. Админка

- Приоритет — планшет и десктоп (`medium`/`wide`): мастера, таблицы участников, импорт CSV, аудит.
- На `compact` доступны **только базовые действия**: правка счёта, DQ/WD, поиск игрока, live-контроль (старт/финиш раунда). Создание турнира и настройка поля на телефоне — read-only с подсказкой «удобнее на планшете» (исключение из «всё через UI» зафиксировано осознанно: полевой сценарий правки счёта сохранён).
- Импорт/экспорт файлов — с `medium` и выше.

## 6. Тач-эргономика

- Минимальный таргет 48×48px, gap между разрушительными и обычными действиями ≥8px.
- Критические CTA (ввод счёта, подтверждение) — в нижней трети экрана (`compact`), зона большого пальца правой руки (правша дефолт; настройка «левша» зеркалит Numpad).
- Свайпы счётокарты отключены, когда текстовое поле в фокусе; конфликт с pull-to-refresh решается отключением PTR внутри `/play` (SW сам докачивает).
- Никаких hover-only раскрытий: вся информация доступна тапом; hover — лишь усиление на `wide`.
- Скролл-цепочка: внутренний скролл таблиц не «захватывает» жест возврата браузера (overscroll-behavior).

## 7. Ландшафт

- Счётокарта (compact-ландшафт): карточка лунки слева (40%), Numpad справа (60%) — ввод без скролла.
- Лидерборд: набор колонок по фактической ширине.
- TV-режим `?tv=1`: рассчитан на 16:9 ≥1366px; на меньших — обычный адаптив.

## 8. Яркое солнце, перчатки, темнота (полевые режимы)

| Условие | Поведение |
|---|---|
| Яркое солнце | Переключатель «Солнце» в шапке (1 тап): токены `data-contrast="sun"` — контраст цифр ≥7:1, убраны blur/тени/прозрачности, увеличен вес цифр, увеличены разделители. Проверка: axe-контраст + скриншоты высокой яркости (эмуляция: белый фон-подложка + принудительный `sun`) |
| Перчатки | Все полевые контролы ≥48px; без двойных тапов и лонг-прессов в основном потоке ввода; проверка Playwright-тачем с radius 8px |
| Темнота | Тёмный вариант токенов; After Dark — нативно; яркость акцентов ограничена (нет чистого белого на полный экран), уважение `prefers-color-scheme` |
| Слабая сеть | Индикатор связи всегда виден в шапке (`онлайн`/`офлайн`/`N в очереди`), синхронизация фоновая, ввод не блокируется никогда |
| Долгий раунд | Battery-saver: `prefers-reduced-motion`-поведение + пауза SSE в фоне (докачка по возврату); без wake-lock по умолчанию |

## 9. Типографика и локаль

- Минимальные размеры: цифра счёта на `compact` ≥28px текста (ввод ≥40px), имя игрока ≥15px, вторичный текст ≥13px.
- Zoom 200%: сетки превращаются в карточки, функционал не теряется; text-only zoom не ломает Numpad.
- Длинные строки локалей (+30%): кнопки переносятся/сжимаются, Numpad сохраняет сетку; проверка pseudo-locale.
- RTL: Numpad зеркалится, порядок колонок лидерборда не меняет семантики (позиция всегда с края по dir), проверка снимками.
